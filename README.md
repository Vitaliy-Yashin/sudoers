# 🛡️ Централизованное управление пользователями через IaC

## 📝 Введение

Для инженера, работающего с файлами, директориями и параметрами unit-файлов для фоновых процессов (демонов), важно обеспечить корректное управление пользователями в системе, чтобы не возникало проблем с доступом. Будь то администраторы, DevOps-инженеры, разработчики или сервисные записи — всем нужны свои права и доступы.

## ❌ Проблема

В рамках сети используется несколько серверов. Если выполнять одно и то же действие по созданию или изменению пользователей на каждом сервере вручную, то:

- Тратится много времени.
- Растёт вероятность ошибок из-за человеческого фактора.
- Трудно поддерживать единообразие конфигурации.

Особенно это становится заметно, когда серверов становится больше, а пользователей — не меньше.

## ✅ Решение

Чтобы упростить и ускорить этот процесс, я принял решение описать желаемое состояние пользователей в виде кода с использованием подхода **Infrastructure as Code (IaC)**. В качестве инструмента выбран **Ansible**.

В этом репозитории я реализовал управление пользователями на примере настройки `sudo` для групп:

- **admins** — полный доступ к системе.
- **devops** — доступ для автоматизации и управления инфраструктурой.

Такой подход позволяет:

- Гибко задавать параметры пользователей (SSH-ключи, пароли, списки групп).
- Избежать ошибок при ручном администрировании.
- Экономить время при добавлении нового сервера или пользователя.
- Хранить всю конфигурацию в Git и отслеживать изменения.

## ⚙️ Требования к окружению
Проект протестирован и гарантированно работает в следующей конфигурации:

### 💻 На управляющем узле -Control Node (Место, откуда вы запускаете плейбук )
* **Ansible:** `2.16.3` (на этой версии велась разработка. Проверить свою версию: `ansible --version`).
* **Python:** `3.12.3`

### 🖥️ На целевых серверах (из hosts.ini):
* **ОС:** Ubuntu / Debian (плейбук настраивает конфигурацию для Linux систем).
* **Служба SSH:** На каждом сервере должен быть установлен и запущен `ssh-server`.
* **Доступ по ключу:** Управляющий узел должен подключаться к удаленным серверам по SSH-ключу без ввода пароля.
* **Права Ansible-пользователя:** Пользователь, под которым Ansible подключается к серверам (например, пользователь с правами sudo), должен иметь возможность выполнять команды с повышением привилегий (`become: true`) **без запроса пароля** (настройка `NOPASSWD` в sudoers на целевой машине). Это необходимо, так как проект управляет системными правами и доступом других пользователей.

## 📂 Структура проекта
```text
.
├── files/               # Системные конфигурационные файлы
├── group_vars/          # Общие переменные для групп хостов
├── roles/               # Директория с логикой автоматизации (роли)
│   ├── admins/          # Роль для создания и настройки администраторов
│   └── devops/          # Роль для настройки DevOps-инженеров
├── hosts.ini            # Настройки подключения к вашим серверам
├── playbook.yml         # Главный файл для запуска всех ролей
└── requirements.yml     # Внешние роли и коллекции Ansible
```

## 🚀 Как запустить

1. **Клонировать репозиторий:**
```bash
git clone https://github.com/Vitaliy-Yashin/sudoers.git && cd sudoers
```
2. **Настроить инвентарь в hosts.ini:**
```ini
[hosts]
161.104.55.40 ansible_port=22 ansible_user=vitaliy
```
3. **Установить зависимости**
```bash
ansible-galaxy install -r requirements.yml --force
```
4. **Настроить параметры пользователей:**
Отредактируйте файлы под свои цели в `roles/devops/vault/secret.yml` или `roles/admins/vault/secret.yml`. 

🔒 Файлы зашифрованы в целях безопасности. Расшифровать их для редактирования можно следующей командой:
```bash
ansible-vault decrypt roles/devops/vault/secret.yml roles/admins/vault/secret.yml
#Дефолтный пароль: 123
```
📝 После этого файлы примут следующий вид, доступный для кастомизации:
```yaml
devops:
  - name: "alex"
    groups: sudo
    ssh_keys: "ssh-ключ"
    password: "123456789"
```
5. **(Опционально) Зашифровать файлы обратно:**
Сделайте это перед отправкой в Git. Используйте команду ниже и задайте свой собственный надежный пароль:
```bash
ansible-vault encrypt roles/devops/vault/secret.yml roles/admins/vault/secret.yml
```

6. **Запуск плейбука:**

* **🔓 Если файлы остались незашифрованными:**
```bash
ansible-playbook -i hosts.ini playbook.yml
```

* **🔒 Если файлы зашифрованы:**
```bash
ansible-playbook -i hosts.ini playbook.yml --ask-vault-pass 
#Укажите собственный пароль (или дефолтный "123", если вы его не меняли)
```
